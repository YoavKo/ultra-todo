# ultra-todo — Implementation Plan (Flask, local-first, he + en)

## Context
Greenfield project in `ultra-todo/` (Python 3.12, git 2.43). Build the self-hosted GitOps task manager from the design doc: JSON5 task files in `<repo>/.todo/tasks/`, a global SQLite index in the OS cache dir, HEAD-hash cache invalidation, DAG dependency validation, served by Flask + waitress. Added requirement: **full Hebrew + English support** — translated UI, RTL layout, correct Hebrew content handling, language chosen via CLI default plus in-UI toggle; **tags** with filtering; per-task **comments** with attachments; **uv** support.

Added later: **Markdown** in descriptions and comments with an Edit/Save/Cancel description editor and a Preview toggle; **attachments on the ticket description** and a **per-ticket directory** (`<ID>/main.json5`), shorter comment ids, a `migrate` command for the old layout; **priority** (high / medium / low); a **dependencies panel** on the task page (what blocks it and what it blocks, one-click removal); **several repos at once** with automatic free-port selection; a **known-repos list** with `ls` / `open` / `forget` commands; and a `utd` bash shortcut with tab completion; then **terminal commands** to browse and change tickets without the browser (`utd REPO ls|board|next|new|pull|save|migrate|ID …`).

## Core engine (`engine.py`)
- **Cache path**: `platformdirs.user_cache_dir("ultra-todo")/app_global_index.sqlite3`. Tables `projects`, `tasks`, `dependencies` exactly as in the doc. Add `PRAGMA journal_mode=WAL`, `foreign_keys=ON`, and one connection per request/thread (waitress is multi-threaded); writes serialized with a lock.
- **Tags**: tasks get a `tags: []` list in the JSON5 file. Normalize on write (NFC, trim, collapse whitespace, case-fold for matching but preserve display casing of first use, dedupe, max length); Hebrew tags are fully supported. New SQLite table `task_tags(project_path, task_id, tag, tag_key)` with composite PK `(project_path, task_id, tag_key)` and an index on `(project_path, tag_key)`; `tag_key` is the casefolded/NFC form used for filtering. Hydration (full + differential) and mutations maintain it alongside `tasks`. Bump a `schema_version` (PRAGMA user_version) and rebuild the index on mismatch — the cache is disposable, so migration = drop + rehydrate.
- **Comments (discussion thread)**: each task owns a directory `.todo/tasks/<ID>/` (created lazily). One file per comment — `.todo/tasks/<ID>/comments/<YYYYMMDD-HHMMSS>-<hex>.json5` (UTC time + 6 random hex, e.g. `20261018-100000-ab12cd`; `created_at` keeps milliseconds so comments added within one second stay ordered; the older `20261018T100000123Z-ab12cd` ids are still accepted) with `{id, author, created_at, edited_at?, body, attachments:[{name, file, mime, size}]}` — so two people commenting concurrently never touch the same file (zero-conflict pillar; a single `comments[]` array in the task file would conflict). Scanner globs `.todo/tasks/*/main.json5` (and the legacy flat `*.json5`) for tasks and `<ID>/comments/*.json5` for comments.
  - **Author/time**: server stamps `created_at` (UTC ISO-8601) and author from `git config user.name`/`user.email` (falls back to OS user; `--author` override). Client-supplied values ignored. Displayed in the viewer's locale/timezone (Babel).
  - **Order**: newest first (`ORDER BY created_at DESC, id DESC`).
  - **Edit**: only the comment body (and adding/removing attachments) via `POST /task/<id>/comment/<cid>`; sets `edited_at`, shows an "edited" badge. Delete supported (removes file + its attachments). Edit/delete permitted only for the same author (local-trust tool, but prevents accidents) — easy to relax. Git history provides the real audit trail.
  - **Attachments** (images/files): stored at `.todo/tasks/<ID>/attachments/<comment-id>/<sanitized-name>`, or `attachments/description/<name>` for files attached to the ticket's own description (listed in `main.json5` as `attachments:[{name,file,mime,size}]` and indexed in a `tasks.attachments` column; the same attachment route serves both, with `description` in place of the comment id); filename sanitized (strip path parts, NFC, collision-suffix), size cap (default 10 MB, configurable `--max-attachment-mb`), served via `GET /task/<id>/attachment/<cid>/<name>` with `Content-Disposition` and `X-Content-Type-Options: nosniff`; only raster images (png/jpg/gif/webp) inline-rendered as thumbnails/lightbox — SVG/HTML always forced download to avoid script execution. Path traversal blocked by resolving and checking the path stays under the task dir.
  - **Caveat vs. design doc**: attachments are user content in the repo (not DB binaries), so the "text-only repo" pillar becomes "no *app* binaries"; document recommending Git LFS for large files. Auto-commit stages the comment file + its attachments only.
  - **Index**: table `comments(project_path, task_id, id, author, created_at, edited_at, body)`, composite PK `(project_path, task_id, id)`, index on `(project_path, task_id, created_at DESC)`; `attachments` rows optional (or derived from the comment file). Hydration/differential hydration/delete handling extended to comment paths; comment body also searchable. Task card shows a comment count.
  - **Rendering**: comment body is escaped plain text with auto-linking and line breaks (or sanitized Markdown, decision deferred); `dir="auto"` for Hebrew/English mixes. Paste-an-image and drag-drop upload in the comment box (vanilla JS, `multipart/form-data`, CSRF token).
- **Task file**: `.todo/tasks/<ID>/main.json5` — the ticket's directory also holds its `comments/` and `attachments/`. Fields `id,title,status,priority,assignee,description,tags[],blocked_by[]` (+ optional `lang`, `attachments[]`). **Older layout**: `.todo/tasks/<ID>.json5` is still read, and a flat ticket is edited in place; `task_path()` picks the nested file if it exists, else the flat one, and the nested one wins if both exist. `ultra-todo REPO migrate` (`Engine.migrate_layout`) `git mv`s flat files into place without committing; duplicates that are byte-identical are dropped, differing ones are reported as conflicts. The app and `utd REPO` warn while flat files remain. Extra user fields are kept on save. Read with `json5`; write deterministically (sorted keys, 2-space indent, trailing newline, `ensure_ascii=False` so Hebrew stays readable and diffs are clean). Write atomically (temp file + `os.replace`). Validate `ID` against `^[A-Za-z0-9_-]+$` to prevent path traversal.
- **Boot/hydration**: `git rev-parse HEAD` → compare with `projects.last_scanned_commit`.
  - Hit → skip scan. Missing row → full hydrate. Differ → `git diff --name-status <old> HEAD -- .todo/tasks` and handle A/M/D/R (deletions remove rows; renames = delete+add). Fall back to full hydrate if `<old>` is unreachable (rebase/gc) or diff fails.
  - **Gap in the doc to resolve**: HEAD alone misses *uncommitted* edits to `.json5` files (hand edits, `--auto-commit` off). Plan: also fold `git status --porcelain -- .todo/tasks` into the cache key (HEAD + hash of dirty-file list/mtimes); if dirty, re-parse just those files. Non-git targets: error out with a clear message.
- **Mutation**: validate → graph check → write file → update SQLite in one transaction → if `--auto-commit`, `git add <file>` + `git commit -m "task: update <ID>"` (only that path) → store new HEAD in `last_scanned_commit`. If the file write fails, no DB change; if the commit fails, report but keep file+DB consistent (cache key uses dirty state, so it self-heals).

## Sync buttons: Update and Save work (`engine.py` git helpers, header buttons)
- **Update** (`POST /sync/pull`): `git pull --ff-only` in the target repo, then run the existing differential hydration from the old HEAD to the new HEAD (A/M/D/R for tasks, comments and tags), so only changed files are re-parsed. Shows a summary toast ("3 tasks updated, 1 added, 2 comments"). Rules:
  - Needs an upstream; with no remote/upstream the button is disabled with a tooltip.
  - If the branch diverged (ff-only fails), offer "Update with rebase": `git pull --rebase --autostash`. On a conflict run `git rebase --abort` (and restore the stash), then report the conflicting files so the user resolves them in git. The app never leaves the repo mid-rebase.
  - Uncommitted `.todo/` edits are handled by `--autostash`; the cache key (HEAD + dirty list) is recomputed afterwards.
- **Save work** (`POST /sync/save`): stage only `.todo/` (`git add -- .todo`), commit with an editable message (default `tasks: update N task(s)`), then `git push`. Rules:
  - Never stages anything outside `.todo/`. If nothing is staged, skip the commit and just push any unpushed commits.
  - Push rejected (remote ahead) → no force push; tell the user to run Update first. No upstream → offer `git push -u origin HEAD`.
  - After the commit, store the new HEAD in `last_scanned_commit`. With `--auto-commit` on, Save is effectively just the push.
- **Shared plumbing**: all git calls go through one helper with `GIT_TERMINAL_PROMPT=0` and a timeout (no hangs on credential prompts), run under a per-project lock so they cannot interleave with mutations; stderr is surfaced to the user in a translated error dialog. POST + CSRF only.
- **Status** (`GET /api/sync-status`): branch, upstream, ahead/behind (from local refs, no network), count of uncommitted `.todo/` changes. Drives a badge on Save work ("5 changes") and "↑2 ↓1" next to the branch name; Update also runs `git fetch` so behind-counts refresh when clicked.
- Buttons are labeled via Babel (Update / עדכן, Save work / שמור עבודה), show a spinner while running, and are disabled during an operation.

## Graph (`graph.py`)
Build adjacency from `dependencies` for the project, add the proposed edge(s), iterative DFS with white/gray/black coloring (avoids recursion limit); return the cycle path. Routes return HTTP 400 with a translated message plus the cycle path. Also reject self-dependency and unknown IDs.

### Dependencies on the task page
- A "Dependencies" panel near the top of the task page with two lists: **Blocked by** and **Blocks**. Each row shows status, ID and title, linked to the other task.
- **×** on a row removes that link at once (`POST /task/<id>/blocked_by/<blocker>/delete`), from either side; the user stays on the page they were on.
- A picker + Add in each list (`POST /task/<id>/dependency` with `kind=blocked_by|blocks`); a link that would create a cycle is rejected with a message.
- A "Waiting on N open tasks" warning when blockers aren't done. Board cards show ⛔ N (blocked by) and ➜ N (blocks).
- Saving the main task form never changes blockers (so they can't be cleared by accident); only the New task form picks blockers, with checkboxes.

## Priority
- `priority` field: `high | medium | low`, default `medium` (also for existing tasks without it). Other values fail validation.
- Index: `priority` and `priority_rank` columns on `tasks` (bumped `SCHEMA_VERSION` → index rebuilt automatically).
- UI: coloured badge (▲ high, ● medium, ▼ low) on cards and in the list, plus a coloured card edge; form field, list column and a filter in the filter bar.
- Sorting: board columns and the list order by priority (high first), then ID.

## Hebrew + English (`i18n.py`, templates, CSS)
- **UI strings**: Flask-Babel, all templates use `_()`; `.po` catalogs for `en` and `he`; `pybabel extract/init/compile` documented. Plural forms handled per catalog (Hebrew has distinct plural rules).
- **Locale resolution order**: `?lang=` → cookie `lang` (set by header toggle) → CLI `--lang` default → `Accept-Language` best match → `en`.
- **Direction**: `<html lang="{{locale}}" dir="{{'rtl' if locale=='he' else 'ltr'}}">`. CSS written with **logical properties** (`margin-inline-start`, `padding-inline`, `text-align: start`, `inset-inline-*`) so one stylesheet serves both; Kanban column order, drag-drop affordances and icons that imply direction (arrows, chevrons) flip via `[dir=rtl]`.
- **Content**: task title/description rendered in elements with `dir="auto"` (or the task's `lang` if set) so a Hebrew task inside an English UI (and vice versa) displays correctly; inputs also `dir="auto"`; IDs/hashes/paths wrapped in `<bdi>`/`dir="ltr"`. Fonts with Hebrew glyphs in the stack.
- **Data handling**: UTF-8 everywhere (file I/O, SQLite, HTTP). Status values stay as stable English keys in the files (`todo|in_progress|done|blocked`) and are *translated only at display time*, so repos stay language-neutral. Search uses Unicode-aware case-folding and NFC normalization (Hebrew niqqud/geresh handled by normalizing on both index and query).
- **Dates/numbers** formatted via Babel for the active locale.

## Markdown, and the description editor (`markup.py`, `task.html`, `app.js`)
- **Renderer** (`markup.render`, template global `md(text, task_id, owner, attachments)`): `markdown-it-py` CommonMark preset with `html: False` (raw HTML is escaped, not passed through), `linkify` (bare URLs; needs `linkify-it-py`), `breaks: True` (a newline is a `<br>`, what the old plain-text comments did, so existing text renders as before), tables, strikethrough and task lists (`mdit-py-plugins`). The library's link validation drops `javascript:`, `vbscript:`, `file:` and non-image `data:` targets. A core rule adds `dir="auto"` to paragraphs, headings, list items, quotes and table cells (Hebrew and English paragraphs each face the right way; code is forced LTR in CSS), `rel="noopener noreferrer" target="_blank"` to external links, and `loading=lazy referrerpolicy=no-referrer` to images. A relative reference that names an attachment (`shot.png`, `attachments/description/shot.png`) is rewritten to the attachment route: in the description against the description's files, in a comment against that comment's. The old regex `linkify` filter is gone.
- **Description**: shown rendered in its own section of the task page with an **Edit** link; Edit hides the view and shows a form (`POST /task/<id>/description`, multipart: the textarea, the existing attachments with Remove, a file input) with Save and Cancel (Cancel resets the form; Esc cancels, Ctrl/Cmd+Enter saves). The main task form no longer carries the description, and `form_task` only reads keys the form actually has, so saving the title can never blank the description. The new-task form keeps a description box.
- **Preview**: `POST /api/markdown {text, task_id?, owner?}` returns the rendered HTML (CSRF-protected like the other JSON calls; `owner` is `description` or a comment id so file names resolve); the Preview/Write toggle on the description editor, the comment composer and the comment editor swaps the textarea for it (the HTML is what the server produced from escaped text, so `innerHTML` is safe).
- A global `[hidden] { display: none !important }` makes the `hidden` attribute win over `display: flex` rules (hidden forms had been showing).

## UI / routes (`app.py`)
`/` Kanban board by status (filters: assignee, text, priority, **tags**), `/list`, `/task/<id>` view/edit, `POST /task` create, `POST /task/<id>` update, `POST /task/<id>/status` (drag-drop), `POST /lang` (set cookie), `GET /api/graph`, `GET /api/tags` (all tags + counts, for autocomplete/filter chips), `POST /task/<id>/comment` (create, multipart), `POST /task/<id>/comment/<cid>` (edit), `POST /task/<id>/comment/<cid>/delete`, `GET /task/<id>/attachment/<cid>/<name>`, `POST /task/<id>/dependency` and `POST /task/<id>/blocked_by/<blocker>/delete` (add/remove links), `POST /sync/pull`, `POST /sync/save`, `GET /api/sync-status`. The task page shows the comment composer above a newest-first thread.
- **Tag UI/filtering**: tag chips on cards; tag input with autocomplete (Enter/comma to add, Backspace removes) in the task form; filter bar of clickable tag chips on board and list. Filter state lives in the URL (`?tag=a&tag=b&match=any|all`, default `all`/AND; "any" toggle) so views are shareable/bookmarkable; query uses `tag_key` joins with `GROUP BY ... HAVING COUNT(DISTINCT tag_key)=N` for AND. Combines with assignee/text filters. Chips use `dir="auto"` so Hebrew tags render correctly; tag-name UI labels translated. Small vanilla JS for drag-and-drop and language toggle. Launch: `uv run ultra-todo --target PATH [--lang he|en] [--port N] [--auto-commit]` (or `python src/app.py ...`), served via `waitress.serve` bound to 127.0.0.1 by default (local-only tool; also add CSRF token on POSTs).

## Several repos and the command line
- **Several instances at once**: without `--port`, each instance takes the first free port from 8080 up (8080, 8081, …) and logs which repo is served where. The socket is bound up front and handed to waitress, so there is no check-then-bind race. A busy explicit `--port` → one-line error instead of a traceback. The repo name is in the browser tab title. Instances safely share the cache file (WAL, per-project rows).
- **Known-repos list** (`repos.py`): every served repo is recorded in `repos.json` in the user data dir (`~/.local/share/ultra-todo/` on Linux) — not the cache, so clearing the cache doesn't lose it. Repos already in the cache index are imported. (A custom `--db` is not recorded.)
- **`open [REPO]` / `REPO open`**: serve and open the browser. `REPO` goes through `cli.resolve_repo` (name, `ls` number, path, `.`), so a path works as well as a known name; with no REPO it is the repo the current directory is in (error if none). It adds `--browser`; `--no-browser` cancels it, and a plain `serve` only opens a browser with an explicit `--browser`. The socket is already listening before the browser starts (connections queue), so no sleep is needed; `--debug` opens after a short timer because the reloader binds its own socket. A wildcard `--host` opens `127.0.0.1`; a browser that cannot start only logs a warning. `open` and `serve` are reserved words after the repo; inside the REPL they are refused (the server would block the prompt), except that `open` on the current ticket still opens its attachments.
- **`ultra-todo ls`**: numbered list, most recently opened first. Columns: number, last opened (local time), `[x open, y done]`, name, path; `(missing)` if the directory is gone. Open = todo, in progress and blocked. Each repo's index is refreshed first (a cheap cache-hit check), so counts include `git pull`s and uncommitted edits.
- **`ultra-todo open NAME|NUMBER [flags]`**: serve a known repo by name (case-insensitive) or `ls` number; names win over numbers. Two repos with the same name → error listing both paths. Numbers follow the `ls` order, so they shift when another repo is opened (`open 1` = the last one).
- **`ultra-todo forget NAME|NUMBER,...`**: remove repos from the list and their rows from the cache index (otherwise they'd be re-imported). Names and numbers, space- or comma-separated (`3,5`). All are resolved against one listing before anything is removed; if one is unknown, nothing is removed. Missing repos can be forgotten too. The repo's files are never touched; serving it again adds it back.
- **Help**: `-h`/`--help` shows the flags and a commands list; each command has its own help with examples (`ls -h`, `open -h`, `forget -h`).
- **`utd` shortcut**: `shell/utd.bash` (sourced from `~/.bashrc`; it finds the checkout from its own path) defines `utd`, which runs `ULTRA_TODO_PROG=utd uv run --project <checkout> ultra-todo "$@"`. All argument handling is in Python, so the shortcut is a pass-through; `ULTRA_TODO_PROG=utd` makes help and errors speak in `utd` terms. Completion: commands, repo names and directories first, then per repo the actions, ticket ids, values (status, priority) and each command's flags. For a directory named `ls`, write `utd ./ls`.

## Terminal commands (`cli.py`)
`ultra-todo REPO [ACTION …]` (also as `utd REPO …`) works on one repo from the terminal. Everything goes through the same `Engine` calls as the web UI, so validation is identical (cycles, ids, tag normalisation).
- **REPO**: `.` / `..` / any path (starts with `/`, `~`, `./`, `../` or contains a separator) or a known repo's name or `ls` number (`repos.resolve`). An unknown name errors with a hint to write `./name`. `ls`, `open` and `forget` as the first word are the repo-list commands; `utd` alone prints help.
- **Reading**: `deps` = the blocker tree and the tree of what it blocks (transitive, diamonds expanded once and marked `(shown above)`, plus how many unfinished tickets it waits on); no action = project info (branch, upstream, ahead/behind, uncommitted `.todo` changes, counts by status, open by priority and assignee, tags); `ls` = table (filters `--status --priority --assignee -t/--tag --any -q --open --mine`); `board` = four columns of boxed cards (ID, priority mark, `→N` blocks, `✖N` blocked by, `@assignee`, `#tags`), fitted to the terminal width and stacked when it is too narrow; `next` = open tickets whose blockers are all done, high priority first, in-progress first within a priority; `ID` = ticket with blockers, blocked tickets, description and comments. `--json` on info, `ls`, `next` and the ticket view (the index's `project_path` is stripped); `ls --ids` for completion.
- **Ticket lookup**: exact id, else case-insensitive, else a bare number matching exactly one `PREFIX-N`; several matches or none → error.
- **Short forms**: `cli.REPO_ALIASES` (`l list`=ls, `b`, `n`, `i`, `a add`=new, `pl`, `sv`) and `cli.TICKET_ALIASES` (`e c st d ro pr at dt o bl bb t as tg dp del`) are applied in `dispatch` / `cmd_ticket`; a real ticket id (case-insensitive) always wins over an alias, also inside `cd`. REPL-only: `h` and `?` for help, `..` for `cd ..`; completion resolves aliases first (`l --st<Tab>`), and the bash completion lists them in its `case` patterns.
- **Fields**: `title TEXT…`, `assign NAME|me|-`, `tag +A -B C` and `rm [-y]` take the words after them raw (before argparse), so a title or tag may start with a dash; tags keep their existing spelling, `rm` asks on a tty and refuses without `-y` otherwise.
- **Filters and export**: `--blocked` (status blocked or an unfinished blocker), `--since 90m|12h|3d|2w|DATE` (`Engine.last_changed`: one `git log --name-only` pass for the newest commit per ticket, file mtime for uncommitted edits), `ls --sort priority|id|status|title|assignee|comments|updated` with `-r`, `--csv` / `--md` (`ls`), `board --md`; status filters take the same aliases as `status`.
- **Changing** (writes files, never commits; includes `attach FILES` / `detach NAMES` for description attachments and `open [SPECS]` / `-o` to open attachments of the description or any comment with the system opener (`xdg-open` / `open` / `os.startfile`, `--path` prints instead). Attachments are numbered per ticket (description first, then comments oldest first, so numbers are stable); a spec is a number, a name or `OWNER/NAME` (a literal file name beats an index); no spec with several files prompts on a tty, else lists; `detach` takes the same specs but only for description files. `comment -f FILES` attaches files to a comment (files only if `-m` is omitted), `new --attach`, and `migrate`): `new [TITLE] [-p -a -t -d --status --id]` (no title: `$EDITOR`, first line title, rest description); `status VALUE` / `-s` and the shortcuts `start`, `done`, `reopen` (aliases such as `doing`, `wip`); `priority VALUE` / `-p` (`h/m/l`, `med`); `comment` / `-c` with `-m`, `$EDITOR` (git-commit style, `#` lines dropped) or stdin; `edit` / `-e` opens the task file in `$VISUAL`/`$EDITOR` and afterwards validates it (JSON5 parses, canonical fields, id unchanged, no cycle); an invalid file is kept and the error says how to fix or `git checkout` it.
- **Dependencies**: `blocked IDS` / `-b` (this ticket blocks IDS), `block-by IDS` / `-bb` (blocked by IDS), `remove blocked` / `-rb`, `remove block-by` / `-rbb`. One mutating action per call (several dependency flags may be combined). Cycles and self-links are refused; removing a dangling blocker id works.
- **Sync**: `pull [--rebase]` and `save [-m MSG] [--set-upstream]` call `engine.pull` / `engine.save_work` (same rules as the buttons: only `.todo/` is committed, no force-push, conflicts abort cleanly). `SyncError` codes become CLI sentences that name the next command to run. `save` without an upstream has already committed when it asks for `--set-upstream` (engine behaviour, shared with the app).
- **Output**: tables sized with display width (combining marks count 0, wide characters 2), colour only on a tty (off with `NO_COLOR`, forced with `CLICOLOR_FORCE=1`), `✖` instead of an emoji so card borders stay aligned.
- **REPL (`repl.py`)**: `utd REPO repl` (or bare `utd` inside a git repo that has `.todo/tasks`, `cli.cwd_todo_repo`) keeps one `Engine` open and runs each line through the same `cli.dispatch` as the one-shot form (shlex-split; `refresh()` before each command). `SystemExit` from `fail()` / argparse is caught so errors never end the session; built-ins `help`, `use REPO`, `exit|quit|q`, Ctrl-D, `show [ID]` and `cd [ID|..]`; `serve` is refused. **Current ticket**: after `cd ID` the prompt is `repo/ID> ` and a first word that is a ticket action (or a flag) is prefixed with the current id before dispatch; other ids still work, `use` and the ticket disappearing (rm) reset it. Completion takes the current ticket as an argument. Tab completion is a pure function `complete(engine, words_before, current_word)` (testable without a terminal) wired to `readline` (`show-all-if-ambiguous` so one Tab lists; libedit binding on macOS; no completion where `readline` is missing): commands and ids, `use` repo names, per-command flags and values (statuses with aliases, priorities, tags, assignees), ticket actions, other ids for dependency actions (not itself, not already chosen), file names for `attach`/`-f`/`--attach`, and the ticket's attachment numbers/names for `open`/`detach`. History in `repl_history` under the user data dir. Status filters accept the same aliases as `status` (`doing`, `wip`, …).
- **Web Open button**: `POST /task/<id>/open-attachment/<cid>/<name>` calls `cli.launch` (the same opener as `utd … open`).
