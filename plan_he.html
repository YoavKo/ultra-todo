ultra-todo – תוכנית מימוש

מנהל משימות מקומי (Flask), בגישת local-first ו-GitOps, עם תמיכה מלאה בעברית ובאנגלית

הקשר

פרויקט חדש לגמרי בתיקייה ultra-todo/ (Python 3.12, git 2.43). בונים את מנהל המשימות המתואר במסמך העיצוב: קובצי משימה בפורמט JSON5 בתוך <repo>/.todo/tasks/, אינדקס SQLite גלובלי בתיקיית המטמון של מערכת ההפעלה, פסילת מטמון לפי ה-hash של HEAD, אימות תלויות כגרף חסר מעגלים (DAG), והכול מוגש באמצעות Flask ו-waitress.

דרישות שנוספו: תמיכה מלאה בעברית ובאנגלית (ממשק מתורגם, פריסת RTL, וטיפול נכון בתוכן עברי), בחירת השפה דרך דגל שורת פקודה כברירת מחדל ודרך מתג בתוך הממשק; תגיות (tags) עם סינון; תגובות (דיון) בכל משימה, עם קבצים מצורפים ותמונות; ותמיכה ב-uv.

נוספו בהמשך: עדיפות (גבוהה / בינונית / נמוכה); חלונית תלויות בעמוד המשימה (מה חוסם אותה ומה היא חוסמת, עם הסרה בלחיצה); הרצת כמה מאגרים במקביל עם בחירת פורט פנוי אוטומטית; רשימת מאגרים מוכרים עם הפקודות ls / open / forget; וקיצור דרך ל-bash בשם utd עם השלמה בטאב.

מנוע הליבה (engine.py)

  • נתיב המטמון: platformdirs.user_cache_dir("ultra-todo")/app_global_index.sqlite3. הטבלאות projects, tasks, dependencies בדיוק כפי שבמסמך. מוסיפים PRAGMA journal_mode=WAL, foreign_keys=ON, חיבור נפרד לכל בקשה/תהליכון (waitress הוא רב-תהליכוני), וכתיבות מסודרות באמצעות נעילה.
  • תגיות: לכל משימה יש רשימה tags: [] בקובץ ה-JSON5. נרמול בכתיבה (NFC, חיתוך רווחים, צמצום רווחים כפולים, case-fold להתאמה תוך שמירת הכתיב המקורי להצגה, הסרת כפילויות, אורך מקסימלי). תגיות בעברית נתמכות במלואן. טבלה חדשה task_tags(project_path, task_id, tag, tag_key) עם מפתח ראשי מורכב (project_path, task_id, tag_key) ואינדקס על (project_path, tag_key); tag_key הוא הצורה המנורמלת (NFC + casefold) המשמשת לסינון. ההידרציה (מלאה ודיפרנציאלית) והעדכונים מתחזקים אותה לצד tasks. מעלים schema_version (‏PRAGMA user_version) ובונים את האינדקס מחדש כשיש אי-התאמה – המטמון חד-פעמי, לכן "מיגרציה" = מחיקה והידרציה מחדש.
  • תגובות (שרשור דיון): לכל משימה יש תיקייה .todo/tasks/<ID>/ (נוצרת בעת הצורך). קובץ אחד לכל תגובה – .todo/tasks/<ID>/comments/<UTC-ts>-<shortid>.json5 – עם {id, author, created_at, edited_at?, body, attachments:[{name, file, mime, size}]}. כך שני אנשים שמגיבים במקביל אף פעם לא נוגעים באותו קובץ (עקרון אפס-הקונפליקטים; מערך comments[] יחיד בקובץ המשימה היה יוצר קונפליקטים). הסורק מחפש משימות רק ב-.todo/tasks/*.json5 ברמה העליונה, ותגובות ב-<ID>/comments/*.json5.
    • מחבר וזמן: השרת קובע את created_at (UTC, ISO-8601) ואת המחבר מתוך git config user.name/user.email (ברירת מחדל: משתמש מערכת ההפעלה; אפשר לדרוס עם --author). ערכים שנשלחים מהלקוח מתעלמים מהם. התצוגה לפי השפה ואזור הזמן של הצופה (Babel).
    • סדר: החדשות למעלה (ORDER BY created_at DESC, id DESC).
    • עריכה: אפשר לערוך את גוף התגובה (ולהוסיף/להסיר קבצים מצורפים) דרך POST /task/<id>/comment/<cid>; מעדכן edited_at ומציג תווית "נערך". גם מחיקה נתמכת (מסירה את הקובץ ואת הקבצים המצורפים שלו). עריכה/מחיקה מותרות רק למחבר המקורי (כלי מקומי מבוסס אמון, אך זה מונע טעויות) – קל לבטל. היסטוריית git היא מסלול הביקורת האמיתי.
    • קבצים מצורפים (תמונות/קבצים): נשמרים ב-.todo/tasks/<ID>/attachments/<comment-id>/<sanitized-name>; שם הקובץ מנוקה (הסרת רכיבי נתיב, NFC, סיומת למניעת התנגשות), מגבלת גודל (ברירת מחדל 10MB, ניתנת להגדרה ב---max-attachment-mb), הגשה דרך GET /task/<id>/attachment/<cid>/<name> עם Content-Disposition ו-X-Content-Type-Options: nosniff; רק תמונות רסטר (png/jpg/gif/webp) מוצגות בתוך הדף כתמונות ממוזערות/לייטבוקס – SVG ו-HTML תמיד מורדים כהורדה כדי למנוע הרצת סקריפטים. מניעת path traversal ע"י פתרון הנתיב ובדיקה שהוא נשאר בתוך תיקיית המשימה.
    • הסתייגות ביחס למסמך העיצוב: הקבצים המצורפים הם תוכן משתמש בתוך המאגר (לא בינאריים של מסד נתונים), ולכן עקרון "מאגר טקסט בלבד" הופך ל"אין בינאריים של האפליקציה"; מומלץ לתעד שימוש ב-Git LFS לקבצים גדולים. ה-auto-commit מוסיף ל-stage רק את קובץ התגובה ואת הקבצים המצורפים שלה.
    • אינדקס: טבלה comments(project_path, task_id, id, author, created_at, edited_at, body), מפתח ראשי מורכב (project_path, task_id, id), אינדקס על (project_path, task_id, created_at DESC); שורות attachments אופציונליות (או נגזרות מקובץ התגובה). הידרציה, הידרציה דיפרנציאלית וטיפול במחיקות מורחבים לנתיבי התגובות; גוף התגובה גם ניתן לחיפוש. כרטיס המשימה מציג מספר תגובות.
    • תצוגה: גוף התגובה הוא טקסט רגיל עם escape, קישורים אוטומטיים ושבירות שורה (או Markdown מנוקה – ההחלטה נדחתה); dir="auto" לתערובת עברית/אנגלית. הדבקת תמונה וגרירת קבצים לתיבת התגובה (JavaScript רגיל, multipart/form-data, אסימון CSRF).
  • קובץ משימה: .todo/tasks/<ID>.json5 – שדות: id, title, status, priority, assignee, description, tags[], blocked_by[] (ואופציונלית lang). שדות נוספים שהמשתמש הוסיף נשמרים בעת שמירה. קריאה עם json5; כתיבה דטרמיניסטית (מפתחות ממוינים, הזחה של 2 רווחים, שורה חדשה בסוף, ensure_ascii=False כדי שהעברית תישאר קריאה וה-diff נקי). כתיבה אטומית (קובץ זמני + os.replace). ה-ID מאומת מול ^[A-Za-z0-9_-]+$ למניעת path traversal.
  • אתחול והידרציה: git rev-parse HEAD ← השוואה ל-projects.last_scanned_commit.
    • התאמה (hit) ← מדלגים על הסריקה. שורה חסרה ← הידרציה מלאה. הבדל ← git diff --name-status <old> HEAD -- .todo/tasks וטיפול ב-A/M/D/R (מחיקה מסירה שורות; שינוי שם = מחיקה + הוספה). אם <old> אינו נגיש (rebase/gc) או שה-diff נכשל – חוזרים להידרציה מלאה.
    • פער במסמך שיש לסגור: ‏HEAD לבדו לא מזהה שינויים שלא נעשה להם commit בקובצי .json5 (עריכה ידנית, או --auto-commit כבוי). הפתרון: לשלב גם את git status --porcelain -- .todo/tasks במפתח המטמון (‏HEAD + hash של רשימת הקבצים המלוכלכים/mtimes); אם יש שינויים – מנתחים מחדש רק את הקבצים האלה. יעד שאינו מאגר git ← שגיאה ברורה.
  • שינוי (mutation): אימות ← בדיקת גרף ← כתיבת קובץ ← עדכון SQLite בטרנזקציה אחת ← אם --auto-commit: ‏git add <file> + ‏git commit -m "task: update <ID>" (רק הנתיב הזה) ← שמירת ה-HEAD החדש ב-last_scanned_commit. אם כתיבת הקובץ נכשלת – אין שינוי במסד; אם ה-commit נכשל – מדווחים אך שומרים על עקביות קובץ+מסד (מפתח המטמון כולל מצב "מלוכלך", ולכן המערכת מתרפאת מעצמה).

כפתורי סנכרון: עדכון ושמירת עבודה

  • עדכון (Update) – ‏POST /sync/pull: מריץ git pull --ff-only במאגר היעד, ואז הידרציה דיפרנציאלית קיימת מה-HEAD הישן לחדש (A/M/D/R למשימות, תגובות ותגיות), כך שרק קבצים ששונו מנותחים מחדש. מוצג סיכום ("3 משימות עודכנו, 1 נוספה, 2 תגובות"). כללים:
    • נדרש upstream; בלי remote/upstream הכפתור מושבת עם הסבר.
    • אם הענף התפצל (ff-only נכשל) – מציעים "עדכון עם rebase": ‏git pull --rebase --autostash. בקונפליקט מריצים git rebase --abort (ומשחזרים את ה-stash) ומדווחים אילו קבצים מתנגשים כדי שהמשתמש יפתור ב-git. האפליקציה אף פעם לא משאירה את המאגר באמצע rebase.
    • שינויים ב-.todo/ שלא נעשה להם commit מטופלים ע"י --autostash; מפתח המטמון (HEAD + רשימת קבצים מלוכלכים) מחושב מחדש אחר כך.
  • שמירת עבודה (Save work) – ‏POST /sync/save: מוסיף ל-stage רק את .todo/ (‏git add -- .todo), מבצע commit עם הודעה הניתנת לעריכה (ברירת מחדל tasks: update N task(s)), ואז git push. כללים:
    • אף פעם לא מוסיף ל-stage קבצים מחוץ ל-.todo/. אם אין מה לעשות commit – מדלגים עליו ומבצעים push לקומיטים שטרם נדחפו.
    • דחיית push (השרת מקדים אותנו) ← בלי force push; מבקשים מהמשתמש להריץ קודם "עדכון". אין upstream ← מציעים git push -u origin HEAD.
    • אחרי ה-commit שומרים את ה-HEAD החדש ב-last_scanned_commit. כש---auto-commit פעיל, "שמירת עבודה" היא בפועל רק ה-push.
  • תשתית משותפת: כל קריאות git עוברות דרך פונקציית עזר אחת עם GIT_TERMINAL_PROMPT=0 ו-timeout (בלי תקיעה על בקשת סיסמה), תחת נעילה לכל פרויקט כדי שלא יתערבבו עם שינויים אחרים; ה-stderr מוצג למשתמש בדיאלוג שגיאה מתורגם. ‏POST + CSRF בלבד.
  • סטטוס – ‏GET /api/sync-status: ענף, upstream, ahead/behind (מהרפרנסים המקומיים, בלי רשת), ומספר שינויים ב-.todo/ שלא נעשה להם commit. מזין תג על הכפתור "שמירת עבודה" ("5 שינויים") וסימון "↑2 ↓1" ליד שם הענף; "עדכון" מריץ גם git fetch כך שספירת ה-behind מתרעננת בלחיצה.
  • התוויות מתורגמות דרך Babel (Update / עדכן, Save work / שמור עבודה), מוצג ספינר בזמן הפעולה, והכפתורים מושבתים בזמן ריצה.

גרף תלויות (graph.py)

בונים רשימת שכנויות מטבלת dependencies של הפרויקט, מוסיפים את הקשת המוצעת, ומריצים DFS איטרטיבי עם צביעה לבן/אפור/שחור (ללא מגבלת רקורסיה); מחזירים את נתיב המעגל. הנתיבים מחזירים HTTP 400 עם הודעה מתורגמת ונתיב המעגל. בנוסף נדחות תלות עצמית ומזהים לא קיימים.

תלויות בעמוד המשימה

  • חלונית "תלויות" בראש עמוד המשימה עם שתי רשימות: חסומה ע"י וחוסמת את. כל שורה מציגה סטטוס, מזהה וכותרת עם קישור למשימה השנייה.
  • כפתור × בכל שורה מסיר את הקישור מיד (‏POST /task/<id>/blocked_by/<blocker>/delete), מכל אחד משני הצדדים, והמשתמש נשאר בעמוד שבו היה.
  • בורר + "הוסף" בכל רשימה (‏POST /task/<id>/dependency עם kind=blocked_by|blocks); קישור שיוצר מעגל נדחה עם הודעה.
  • אזהרה "ממתינה ל-N משימות פתוחות" כשיש חוסמים שלא הושלמו. על הכרטיסים בלוח: ⛔ N (חסומה ע"י) ו-➜ N (חוסמת).
  • שמירת טופס המשימה הראשי אינה משנה חוסמים (כדי שלא יימחקו בטעות); רק בטופס "משימה חדשה" בוחרים חוסמים בתיבות סימון.

עדיפות

  • שדה priority: ‏high | medium | low, ברירת מחדל medium (גם למשימות קיימות בלי השדה). ערך אחר נדחה באימות.
  • באינדקס: עמודות priority ו-priority_rank בטבלת tasks (העלאת SCHEMA_VERSION ← האינדקס נבנה מחדש אוטומטית).
  • תצוגה: תג צבעוני (▲ גבוהה, ● בינונית, ▼ נמוכה) על הכרטיסים וברשימה, ופס צבע בצד הכרטיס; שדה בטופס, עמודה בתצוגת הרשימה וסינון בסרגל הסינון.
  • מיון: בעמודות הלוח וברשימה – לפי עדיפות (גבוהה קודם) ואז לפי מזהה.

עברית + אנגלית (i18n.py, תבניות, CSS)

  • מחרוזות ממשק: Flask-Babel; כל התבניות משתמשות ב-_(); קטלוגי .po ל-en ול-he; הפקודות pybabel extract/init/compile מתועדות. צורות רבים מטופלות לכל קטלוג (בעברית יש כללי ריבוי נפרדים).
  • סדר קביעת השפה: ‏?lang= ← עוגיית lang (נקבעת ע"י המתג בכותרת) ← --lang משורת הפקודה ← ההתאמה הטובה ביותר מ-Accept-Language ← en.
  • כיוון: ‏<html lang="{{locale}}" dir="{{'rtl' if locale=='he' else 'ltr'}}">. ה-CSS כתוב עם תכונות לוגיות (margin-inline-start, padding-inline, text-align: start, inset-inline-*) כך שגיליון סגנונות אחד משרת את שני הכיוונים; סדר עמודות הקנבן, אפורדנסים של גרירה ואייקונים בעלי כיווניות (חיצים וכו') מתהפכים דרך [dir=rtl].
  • תוכן: כותרת ותיאור משימה מוצגים באלמנטים עם dir="auto" (או לפי lang של המשימה אם הוגדר), כך שמשימה בעברית בתוך ממשק באנגלית (ולהפך) תוצג נכון; גם שדות הקלט עם dir="auto"; מזהים, hash ונתיבים עטופים ב-<bdi>/dir="ltr". גופנים התומכים בעברית ברשימת הגופנים.
  • טיפול בנתונים: ‏UTF-8 בכל מקום (קבצים, SQLite, HTTP). ערכי הסטטוס נשארים מפתחות אנגליים יציבים בקבצים (todo|in_progress|done|blocked) ומתורגמים רק בזמן התצוגה, כך שהמאגרים נשארים ניטרליים לשפה. החיפוש מודע-יוניקוד, עם case-folding ונרמול NFC (ניקוד וגרשיים בעברית מטופלים ע"י נרמול גם באינדקס וגם בשאילתה).
  • תאריכים ומספרים: מעוצבים ע"י Babel לפי שפת הממשק.

ממשק ונתיבים (app.py)

/ – לוח קנבן לפי סטטוס (סינון: אחראי, טקסט, עדיפות, תגיות); /list; /task/<id> – צפייה/עריכה; POST /task – יצירה; POST /task/<id> – עדכון; POST /task/<id>/status – גרירה; POST /lang – קביעת עוגיה; GET /api/graph; GET /api/tags – כל התגיות עם ספירה (להשלמה אוטומטית ולצ'יפים); POST /task/<id>/comment – יצירה (multipart); POST /task/<id>/comment/<cid> – עריכה; POST /task/<id>/comment/<cid>/delete; GET /task/<id>/attachment/<cid>/<name>; ‏POST /task/<id>/dependency ו-POST /task/<id>/blocked_by/<blocker>/delete – הוספה והסרה של תלויות; ‏POST /sync/pull, ‏POST /sync/save, ‏GET /api/sync-status. בעמוד המשימה תיבת כתיבת תגובה מעל שרשור שהחדשות בו למעלה.

  • ממשק תגיות וסינון: צ'יפים של תגיות על הכרטיסים; שדה תגיות עם השלמה אוטומטית (‏Enter/פסיק להוספה, Backspace להסרה) בטופס המשימה; סרגל סינון של צ'יפים לחיצים בלוח וברשימה. מצב הסינון נשמר ב-URL (?tag=a&tag=b&match=any|all, ברירת מחדל all/AND; מתג ל-"any") כך שאפשר לשתף ולשמור סימניה; השאילתה משתמשת ב-join על tag_key עם GROUP BY ... HAVING COUNT(DISTINCT tag_key)=N עבור AND. משתלב עם סינוני האחראי והטקסט. הצ'יפים עם dir="auto" כך שתגיות בעברית מוצגות נכון; תוויות הממשק של התגיות מתורגמות.
  • JavaScript קטן לגרירה ולמתג השפה. הפעלה: uv run ultra-todo --target PATH [--lang he|en] [--port N] [--auto-commit] (או python src/app.py ...), מוגש ע"י waitress.serve כשהוא קשור ל-127.0.0.1 כברירת מחדל (כלי מקומי בלבד; בנוסף אסימון CSRF על כל ה-POST).

כמה מאגרים ושורת הפקודה

  • כמה מופעים במקביל: בלי --port, כל מופע תופס את הפורט הפנוי הראשון החל מ-8080 (‏8080, 8081, …), ושורת הלוג מציינת איזה מאגר מוגש באיזו כתובת. הסוקט נקשר מראש ומועבר ל-waitress, כך שאין מרוץ בין בדיקה לקשירה. ‏--port מפורש שתפוס ← שגיאה בשורה אחת (במקום traceback). שם המאגר מופיע בכותרת לשונית הדפדפן. כמה מופעים חולקים בבטחה את קובץ המטמון (WAL, שורות נפרדות לכל פרויקט).
  • רשימת מאגרים מוכרים (repos.py): כל מאגר שהוגש נרשם ב-repos.json בתיקיית נתוני המשתמש (~/.local/share/ultra-todo/ בלינוקס) – לא במטמון, כדי שניקוי המטמון לא ימחק אותה. מאגרים שכבר נמצאים באינדקס המטמון מיובאים אליה. (‏--db מותאם אישית אינו נרשם.)
  • ultra-todo ls: רשימה ממוספרת, האחרון שנפתח ראשון. עמודות: מספר, זמן פתיחה אחרון (שעון מקומי), [x open, y done], שם, נתיב; ‏(missing) אם התיקייה כבר לא קיימת. "פתוחות" = todo, בעבודה וחסומות. לפני הספירה האינדקס של כל מאגר מתרענן (בדיקת cache-hit זולה), כך שהספירות כוללות git pull ועריכות שלא נעשה להן commit.
  • ultra-todo open NAME|NUMBER [flags]: מגיש מאגר מוכר לפי שם (ללא תלות באותיות גדולות/קטנות) או לפי מספרו ב-ls; שם קודם למספר. שני מאגרים באותו שם ← שגיאה עם שני הנתיבים. המספרים עוקבים אחרי סדר ls, ולכן משתנים כשפותחים מאגר אחר (open 1 = האחרון).
  • ultra-todo forget NAME|NUMBER,...: מסיר מאגרים מהרשימה ואת השורות שלהם מאינדקס המטמון (אחרת היו מיובאים חזרה). שמות ומספרים, מופרדים ברווח או בפסיק (3,5). כולם מפוענחים מול אותה רשימה לפני שמשהו נמחק; אם אחד לא מוכר – לא נמחק כלום. אפשר לשכוח גם מאגרים חסרים. קובצי המאגר אינם נוגעים; הגשה מחדש מוסיפה אותו שוב.
  • עזרה: ‏-h/--help מציג את הדגלים ורשימת פקודות; לכל פקודה עזרה משלה עם דוגמאות (ls -h, ‏open -h, ‏forget -h).
  • קיצור הדרך utd (פונקציית bash ב-~/.bashrc, הקוד המלא ב-README): ‏utd [PATH] [flags] מריץ uv run --project <checkout> ultra-todo --target <נתיב מלא> מכל תיקייה; ברירת המחדל היא התיקייה הנוכחית, ודגלים בלבד (utd --lang he) עדיין משתמשים בה. ‏utd ls|open|forget מועברים כמו שהם. ‏utd מגדיר ULTRA_TODO_PROG=utd כך שהעזרה והודעות השגיאה מדברות במונחי utd (ו---target מוסתר). השלמה בטאב: פקודות ותיקיות קודם, שמות מאגרים אחרי open/forget (גם אחרי פסיק), אחר כך דגלים (--lang משלים ל-en/he). לתיקייה בשם ls כותבים utd ./ls.

אימות

  • תגיות (uv run pytest): נרמול וסילוק כפילויות, מעבר הלוך-חזור של תגית בעברית, סינון AND מול OR, עריכת תגית מעדכנת את task_tags, הידרציה דיפרנציאלית מסירה תגיות של משימות שנמחקו, ספירות ב-/api/tags.
  • תגובות: סדר החדשות-למעלה; מחבר וחותמת זמן נקבעים בשרת; עריכה מעדכנת edited_at ונדחית למחבר אחר; העלאה והורדה של קובץ מצורף; ניקוי שם קובץ ודחיית path traversal; SVG מוגש כהורדה; קובץ גדול מדי נדחה; שתי תגובות במקביל יוצרות קבצים נפרדים; מחיקת תגובה דרך git (הידרציה דיפרנציאלית) מסירה את השורה; תגובה בעברית מוצגת בכיוון הנכון.
  • סנכרון (בדיקות עם remote חשוף זמני ושני clones): עדכון מבצע fast-forward והאינדקס משקף משימות ותגובות שנוספו/שונו/נמחקו; ענף מפוצל ← הצעת rebase; קונפליקט ב-rebase ← ביטול, מאגר נקי, רשימת קבצים; שמירה מוסיפה ל-stage רק את .todo/ (קובץ מחוץ אליו נשאר ללא stage); דחיית push ← שגיאה ידידותית ובלי force; בלי upstream ← "עדכון" מושבת ו"שמירה" מציעה push -u; ספירות התג ו-ahead/behind נכונות; שום פעולה לא נתקעת על בקשת סיסמה.
  • תלויות ועדיפות: הסרה והוספה של קישור מכל צד; קישור שיוצר מעגל נדחה; שמירת טופס המשימה לא מוחקת חוסמים; ברירת מחדל medium, ערך לא חוקי נדחה, מיון גבוהה ← בינונית ← נמוכה, סינון לפי עדיפות, תוויות בעברית.
  • מאגרים ופורטים: שני מופעים בלי --port מקבלים פורטים שונים; פורט מפורש תפוס ← שגיאה ברורה; רישום ופתיחה לפי שם (ללא תלות באותיות) ולפי מספר; שם כפול ← שגיאה; מאגר חסר מדולג ב-open; ייבוא מהמטמון; ‏forget לפי מספרים ושמות, הכול-או-כלום, ולא מיובא חזרה; ספירות [open, done] כוללות עריכות שלא נעשה להן commit.
  • ‏uv sync מ-checkout נקי עובד; ‏uv run ultra-todo --help רץ.
  • pytest כללי: הידרציה (hit/miss/diff/מחיקה/שינוי שם); שינוי שלא נעשה לו commit מזוהה; מעגל ← 400; ID עם path traversal נדחה; כותרת בעברית עוברת קובץ ← SQLite ← HTML ללא שינוי; סדר קביעת השפה; תכונת dir לכל שפה.
  • ידני: יוצרים מאגר git זמני עם .todo/tasks/, מריצים, מוודאים שהאתחול השני מדלג על הסריקה (שורת לוג "cache hit"), עורכים קובץ ידנית ודרך commit בסגנון git pull ומוודאים רענון. מחליפים he↔en: הפריסה מתהפכת, משימה בעברית עם ID באנגלית מוצגת נכון, גרירה עובדת ב-RTL. מוודאים ש-git status במאגר היעד מציג רק שינויים בקובצי .json5 (וקבצים מצורפים של משתמש) – ללא בינאריים של האפליקציה.
